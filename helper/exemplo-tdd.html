Exemplo de Fluxo TDD Completo

🧪 Test-Driven Development no ProsoftAgileAgent

Exemplo prático completo de como implementar funcionalidades seguindo TDD rigoroso: testes primeiro, código depois.

Princípios TDD

O Que é TDD?

Test-Driven Development (TDD) é uma metodologia onde os testes são escritos ANTES da implementação do código. No ProsoftAgileAgent, seguimos rigorosamente:

  1. 🔴 Red: Escrever teste que falha (funcionalidade não existe ainda)
  2. 🟢 Green: Implementar código mínimo para passar no teste
  3. 🔵 Refactor: Melhorar código mantendo testes passando

Sequência de Agentes TDD:

1. Testing Specialist (TDD)    → Cria PLANO DE TESTES completo
   └─ Saída: 05-qa-plano.md

2. Expert Developer (TDD)      → Implementa seguindo plano TDD
   └─ Saída: 04-desenvolvimento.md + código

3. Testing Validator (TDD)     → Valida implementação vs plano
   └─ Saída: 05.1-testing-validation.md

Exemplo Prático: Sistema de Comissões

Funcionalidade: Cálculo de Comissão Base

Regra RN-0030: Comissão base = vendas_mes * percentual_fixo (2.5%)

Passo 1: Testing Specialist cria plano TDD

## Cenário: Cálculo comissão base vendedor
**Given** um vendedor com ID 123
**And** percentual fixo de comissão de 2.5%
**And** vendas do mês de R$ 100.000,00
**When** calcular comissão base
**Then** comissão base deve ser R$ 2.500,00

## Estrutura de Teste Esperada:
```csharp
public class ComissaoBaseCalculatorTests
{
    [Fact]
    public void DeveCalcularComissaoBase_QuandoVendasValidas()
    {
        // Arrange
        var vendas = 100000m;
        var percentual = 0.025m;
        var calculator = new ComissaoBaseCalculator();

        // Act
        var resultado = calculator.Calcular(vendas, percentual);

        // Assert
        Assert.Equal(2500m, resultado);
    }

    [Fact]
    public void DeveLancarExcecao_QuandoVendasNegativas()
    {
        // Arrange
        var vendas = -1000m;
        var percentual = 0.025m;
        var calculator = new ComissaoBaseCalculator();

        // Act & Assert
        Assert.Throws(
            () => calculator.Calcular(vendas, percentual)
        );
    }
}
```

Passo 2: Expert Developer implementa (Ciclo Red-Green-Refactor)

## 🔴 RED: Executar testes (falham - classe não existe)
```bash
dotnet test
# Resultado: 0 passed, 2 failed
```

## 🟢 GREEN: Implementar código mínimo
```csharp
public class ComissaoBaseCalculator
{
    public decimal Calcular(decimal vendas, decimal percentual)
    {
        if (vendas < 0)
            throw new ArgumentException("Vendas não podem ser negativas", nameof(vendas));

        return vendas * percentual;
    }
}
```

```bash
dotnet test
# Resultado: 2 passed, 0 failed ✅
```

## 🔵 REFACTOR: Melhorar código (manter testes verdes)
```csharp
public class ComissaoBaseCalculator
{
    private const decimal PERCENTUAL_MINIMO = 0m;
    private const decimal PERCENTUAL_MAXIMO = 1m;

    public decimal Calcular(decimal vendas, decimal percentual)
    {
        ValidarVendas(vendas);
        ValidarPercentual(percentual);

        return Math.Round(vendas * percentual, 2);
    }

    private void ValidarVendas(decimal vendas)
    {
        if (vendas < 0)
            throw new ArgumentException(
                "Vendas não podem ser negativas",
                nameof(vendas));
    }

    private void ValidarPercentual(decimal percentual)
    {
        if (percentual < PERCENTUAL_MINIMO || percentual > PERCENTUAL_MAXIMO)
            throw new ArgumentException(
                $"Percentual deve estar entre {PERCENTUAL_MINIMO:P0} e {PERCENTUAL_MAXIMO:P0}",
                nameof(percentual));
    }
}
```

```bash
dotnet test
# Resultado: 2 passed, 0 failed ✅ (ainda verde após refactor)
```

Passo 3: Testing Validator valida implementação

## Validação Checklist:
✅ Todos testes do plano executados (2/2 GREEN)
✅ Cobertura de código: 100% (linha e branch)
✅ Performance: <1ms (target <100ms para lote)
✅ Validações implementadas conforme RN-0030
✅ Edge cases cobertos: vendas negativas, percentual inválido
✅ Refatoração não quebrou testes

**Status:** APROVADO ✅

Benefícios do TDD

Design melhor

Pensar em testes primeiro força interfaces limpas e desacopladas

Documentação viva

Testes documentam comportamento esperado da funcionalidade

Confiança para refatorar

Testes garantem que mudanças não quebraram funcionalidades

Menos bugs produção

Cobertura 95%+ reduz drasticamente defeitos em produção

Feedback rápido

Testes executam em segundos, detectam problemas imediatamente

Rastreabilidade

Requisito → Teste → Código → Validação (evidências completas)
